# Knowledge Agent 云端轻量部署设计

## 目标

在现有阿里云 ECS 上与旧项目同时运行 `knowledge_agent`，保持单一代码库：本地环境可启用完整模型能力，ECS 通过环境变量关闭高资源组件。部署不得覆盖旧项目，不得将密钥、模型、业务数据或运行日志提交到 GitHub。

## 已确认环境

- ECS：Ubuntu 22.04 64 位，2 vCPU，4 GiB 内存，84 GiB 系统盘，无 GPU，1 Mbps 公网带宽。
- 旧项目：保留现有目录、进程和 `7860` 端口。
- 新项目目录：`/opt/knowledge_agent`。
- 访问方式：没有域名，暂时使用公网 IP 和独立端口访问。

## 运行模式

### 本地全量模式

完整代码与功能保持不变。用户安装完整依赖、准备 BGE、reranker、VLM 模型并配置 LLM 密钥后，可启用 BGE RAG、reranker、OCR、VLM、对话、工单和知识库管理。

### ECS 轻量模式

使用服务器专属环境变量关闭高资源组件：

```dotenv
VLM_ENABLED=false
RERANKER_ENABLED=false
```

ECS 保留基础 BGE RAG、云端 LLM、登录、对话、工单和知识库管理。关闭项只由部署环境控制，不删除实现代码，不建立独立轻量分支。

## 跨平台路径

- BGE、reranker 和 VLM 默认路径改为相对项目根目录的 `models/`。
- 允许使用环境变量覆盖模型、SQLite、Chroma 和上传文档路径。
- Windows 本地路径与 Linux ECS 路径均通过 `pathlib.Path` 解析。
- 不把模型文件放入 Git；README 提供模型目录结构和准备说明。

## 服务结构

- FastAPI：`127.0.0.1:8000`，仅供本机 Streamlit 调用。
- Streamlit：`0.0.0.0:8501`，公网通过 `http://<公网 IP>:8501` 访问。
- 两个 systemd 服务分别守护 FastAPI 和 Streamlit，并配置自动重启。
- 创建约 4 GiB Swap，降低两个项目同时运行时的内存溢出风险。
- 不使用 Docker，减少 4 GiB ECS 上的额外资源占用和构建复杂度。

## 数据和密钥边界

- GitHub 仅保存源码、测试、文档和无密钥部署模板。
- `.env`、`datas/`、`models/`、日志、SQLite、Chroma 均不提交。
- ECS 的 `.env` 仅由服务账户读取，并限制文件权限。
- 首次部署可单独上传所需 BGE 模型和初始知识文档；业务数据库不从开发机直接覆盖，除非部署前明确确认。

## 公网安全

- 公共注册接口只能创建普通用户，忽略或拒绝客户端提交的管理员角色。
- 管理员账号在服务器本机通过一次性命令创建，不开放公网管理员注册。
- FastAPI 的 `8000` 端口不加入安全组公网规则。
- 安全组仅新增前端 `8501/TCP`；现有规则不在本任务中删除或改写。
- 当前无域名，因此第一阶段为 HTTP 演示访问；后续购买域名后再配置 Nginx 和 HTTPS。

## GitHub 使用说明

README 增加两套说明：

1. 本地全量运行：完整依赖、模型目录、环境变量和启动命令。
2. ECS 轻量运行：禁用项、资源边界、systemd 安装及验证命令。

克隆仓库不会自动获得模型、密钥或业务数据；文档必须明确这些前置条件，避免宣称开箱即用。

## 验证标准

### 本地验证

- 全量 pytest 通过。
- 模型路径在 Windows 和 Linux 风格项目路径下可解析。
- 轻量环境变量关闭 VLM 与 reranker，同时核心 API 测试通过。
- 公共注册不能获得管理员权限。
- Git 暂存清单不包含密钥、模型、数据、日志或测试临时目录。

### ECS 验证

- 旧项目和 `7860` 端口保持可用。
- FastAPI `/health` 从服务器本机返回成功。
- Streamlit 公网页面可打开。
- 登录、基础知识检索、LLM 对话、创建工单和管理员处理工单各验证一次。
- 重启两个 systemd 服务后数据仍存在。
- 观察内存、Swap 和日志，确认没有持续 OOM 或重启循环。

## 回退方案

- 新项目使用独立目录和独立服务，失败时只停止并禁用新服务。
- 不修改旧项目代码、目录和进程。
- 代码更新前记录当前提交；出现回归时切回该提交并恢复新项目自己的 `.env` 与数据备份。
